# 法令データ ダウンロード実行ガイド

e-Gov の XML 一括ダウンロード（bulkdownload）Zip を取得する `laws-ingest download` コマンドの使い方をまとめた運用手順。

- 設計上の位置づけは [`docs/design/12-全件ダウンロード.md`](../design/12-全件ダウンロード.md)（Stage 0: Fetch）および [`docs/design/13-初期取り込み.md`](../design/13-初期取り込み.md) を参照。
- 本コマンドが行うのは **「取得して landing zone に着地させる」までで、Zip 展開・パース・DB 投入は含まない**（後続フェーズ）。

## 前提

- `uv` がインストール済み。
- 依存関係を同期済み（初回のみ）:

  ```bash
  uv sync
  ```

  これで `.venv/bin/laws-ingest` が生成される（`pyproject.toml` の `[project.scripts]` に登録された console script）。

## コマンド書式

```
laws-ingest download [--section {1,2,3}] [--category CD] [--update-date YYYYMMDD] [--full]
```

| オプション | 説明 | 既定 |
|---|---|---|
| `--section` | `1`=全件 / `2`=分類別 / `3`=差分 | `1` |
| `--category` | 分類コード（`--section 2` のとき必須） | なし |
| `--update-date` | 基準日 `YYYYMMDD`（`--section 3` のとき必須。提供は過去 3 か月） | なし |
| `--full` | 画像・様式を含む全データを取得（既定は XML のみ） | XML のみ |

## 基本的な実行例

```bash
# 全件・XML のみ（初期ブートストラップ用。--section 1 が既定なので省略可）
uv run laws-ingest download
uv run laws-ingest download --section 1

# 差分（指定日・XML のみ）
uv run laws-ingest download --section 3 --update-date 20260613

# 分類別（例: 分類コード 001 = 憲法）
uv run laws-ingest download --section 2 --category 001

# 画像・様式を含む全データ（only_xml_flag を外す）
uv run laws-ingest download --section 1 --full
```

> `uv run` は実行のたびに仮想環境を同期し `.venv/bin` を PATH に通す。`source .venv/bin/activate` 済みなら `laws-ingest download …` と直接呼んでもよい。

## 出力

成功すると標準出力に成果物メタ（`DownloadArtifact`）の JSON が表示され、landing zone に生 Zip とサイドカーメタが着地する。

```
var/landing/
└── raw/bulk/{取得日}/section1/
    ├── all_xml.zip            # 取得した生 Zip
    └── all_xml.zip.meta.json  # sha256 / byte_size / http_status / source_url / fetched_at 等
```

- 着地パスは `{DOWNLOAD_LANDING_DIR}/raw/bulk/{captured_date}/section{N}/...`。
- `var/` は `.gitignore` 済みで、取得データはコミットされない。

### 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功 |
| `1` | ダウンロード失敗（リトライ尽き、サーバエラー等） |
| `2` | 引数エラー（必須パラメータ不足など） |

## 設定（環境変数 / `.env`）

挙動は `Settings`（pydantic-settings）の項目を環境変数で上書きして調整する。`.env` ファイルに書いてもよい。

```bash
DOWNLOAD_LANDING_DIR=/data/landing \
DOWNLOAD_USER_AGENT="laws-api-mirror/0.0.1 (+contact@example.com)" \
DOWNLOAD_MAX_RETRIES=8 \
uv run laws-ingest download --section 1
```

| 環境変数 | 既定 | 用途 |
|---|---|---|
| `BULKDOWNLOAD_BASE_URL` | `https://laws.e-gov.go.jp/bulkdownload` | 取得先ベース URL |
| `DOWNLOAD_LANDING_DIR` | `var/landing` | landing zone（生 Zip の着地先） |
| `DOWNLOAD_USER_AGENT` | `laws-api-mirror/{version} (+…)` | 礼儀として付与する User-Agent（連絡先を入れる） |
| `DOWNLOAD_CONNECT_TIMEOUT` | `30.0` | 接続タイムアウト（秒） |
| `DOWNLOAD_READ_TIMEOUT` | `600.0` | 読み取りタイムアウト（秒）。GB 級 Zip 用に長め |
| `DOWNLOAD_MAX_RETRIES` | `5` | 最大試行回数（指数バックオフ） |
| `DOWNLOAD_BACKOFF_BASE` | `2.0` | バックオフの底（`delay = base ** attempt`） |
| `DOWNLOAD_BACKOFF_MAX` | `60.0` | バックオフ上限（秒） |
| `DOWNLOAD_CHUNK_SIZE` | `1048576` | ストリーミング受信のチャンクサイズ（バイト） |

## 動作確認（スモークテスト）

`--section 1`（全件）は **GB 級**の実通信になるため、まず小さい分類で疎通確認するのが安全。

```bash
uv run laws-ingest download --section 2 --category 001   # 憲法（小サイズ）
```

成功後、`var/landing/raw/bulk/.../section2/001_xml.zip` と `.meta.json` が生成されることを確認する。

## 挙動メモ / トラブルシュート

- **再試行**: `429` / `500` / `502` / `503` / `504` は一時障害として指数バックオフで再試行する。`Retry-After` ヘッダがあればその秒数だけ待つ。`4xx`（`404` 等）は回復不能として即失敗。
- **中断・失敗時**: 取得中のデータは `*.part` 一時ファイルに書かれ、完了時にアトミックに本ファイルへ rename される。失敗が確定すると `.part` は削除され、不完全な Zip を成功扱いにしない。
- **冪等性**: メタ JSON に `sha256` を記録する。後続の展開・投入フェーズでは、この値で同一データの再処理をスキップできる（設計 §12.5 / §13.7）。
- **landing zone**: 現状はローカルファイルシステム。本番のオブジェクトストレージ（S3 / SeaweedFS、設計 §11.2 / §12.4）連携は後続フェーズで追加予定。
- **引数エラー例**: `--section 3` を `--update-date` なしで実行すると「`file_section=3 (差分) には update_date が必要です`」と表示して終了コード `2`。
